Reason for change:
  Existing HeadHunter/SuperJob OAuth rows and browser keys were not explicit identities of a first-party User. AUTH-002 makes the verified AI Career Agent account the only browser authentication root and treats providers as encrypted, owner-scoped connections.

Implementation:
  - require first-party login for HH/SuperJob connect;
  - bind OAuth state to random state + TTL + user_id + auth_session_id;
  - atomically create, claim an unbound legacy row, or refresh same-owner connection;
  - forbid email auto-link;
  - reject external identity owned by another User;
  - allow at most one connection per User/provider;
  - add migration 20260811_0009 unique (user_id, provider);
  - keep unique (provider, external_user_id);
  - keep tokens Fernet-encrypted;
  - make dashboard/read/refresh/disconnect owner-scoped;
  - remove legacy provider browser identity authorization;
  - disconnect local unified + rollback mirror credentials by POST + CSRF;
  - add dedicated tests and GitHub gate.
  - synchronize architecture, migration and backup/restore references to candidate revision 20260811_0009.

Security invariants:
  - OAuth code/state are not copied into login next URLs or logs;
  - provider tokens/secrets/profile payloads/external IDs are absent from public logs;
  - state cannot complete under another first-party session;
  - foreign owner rows cannot be read, replaced or deleted;
  - database unique constraints are the final concurrency barrier;
  - no app_fixed.py; WSGI remains app:app.

Explicit exclusions:
  - phone/OTP and social login;
  - admin identity merge/transfer;
  - career profile import;
  - automatic email-based migration;
  - unified remote provider token revocation.
