Reason for change:
  Search, future AI and documents require one owner-scoped, user-confirmed set of structured career facts. Existing OAuth profile snapshots and browser resume-builder data are not a safe first-party profile contract.

Implementation:
  - add one current CareerProfile per first-party User;
  - add immutable CareerProfileVersion full snapshots;
  - add migration 20260811_0010 and backup inventory coverage;
  - support positioning, contacts, goals, geography, salary, skills,
    employment, achievements, education and languages;
  - allow incomplete profiles and expose a non-blocking completion indicator;
  - validate lengths, controlled codes, dates, salary ranges, URLs and duplicates;
  - use deterministic canonical JSON + content hash;
  - create a new version only for material changes;
  - use expected_version, PostgreSQL row lock and unique constraints for concurrency;
  - expose owner-only /profile, /profile/edit, /profile/history and read-only version routes;
  - add dashboard/navigation integration, scoped responsive UI and no-store responses;
  - add migration/service/route/PostgreSQL tests and dedicated GitHub CI gate;
  - synchronize architecture, migration, security, backup and canonical documentation.

Security and privacy invariants:
  - first-party AuthSession is required for every profile route;
  - repository reads/writes/history are owner-scoped by user_id;
  - POST uses CSRF and rate limiting;
  - logs contain only safe changed/version/completion metadata;
  - user facts, contacts and snapshots are not logged;
  - templates escape facts; stored links allow only http/https without credentials;
  - no provider, PDF or AI data is auto-confirmed.

Explicit exclusions:
  - resume import/review (PROF-002);
  - server drafts/autosave/version restore (PROF-003 or later);
  - public profile;
  - AI enrichment/inference;
  - export/delete/retention (PRIV-001);
  - phone/OTP/social identity changes.
