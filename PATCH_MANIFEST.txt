Reason for change:
  Mail.ru is used as a temporary staging transactional sender. Mail.ru documents smtp.mail.ru:465 with SSL/TLS, while the existing adapter supported STARTTLS only.

Fix:
  - add AUTH_SMTP_USE_SSL (default 0);
  - implicit SSL path uses smtplib.SMTP_SSL + default certificate validation;
  - existing STARTTLS path remains backward compatible;
  - production requires at least one secure mode;
  - enabling both STARTTLS and implicit SSL simultaneously is rejected.

Security invariants:
  - no plaintext SMTP in production;
  - no certificate validation bypass;
  - no SMTP password or app password in Git/ZIP/logs;
  - SMTP response/body/recipient remain excluded from failure logs;
  - CSRF strict mode remains unchanged;
  - no migration.
