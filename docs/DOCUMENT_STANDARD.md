# AI Career Agent - стандарт проектных документов

| Поле | Значение |
|---|---|
| Идентификатор | DOC-STD-001 |
| Версия | 1.0 |
| Дата | 06 августа 2026 |
| Статус | ДЕЙСТВУЮЩИЙ |
| Область | PLAN_CURRENT, паспорт, отчёты пакетов, runbooks, source audit |

> Все новые документы проекта должны использовать одинаковую структуру, нумерацию, таблицы статусов и блок доказательств. Свободный текст без явной иерархии не считается каноническим источником.

## 1. Обязательная структура

Каждый документ содержит разделы в следующем порядке:

1. Метаданные документа.
2. Контрольный статус.
3. Цель и границы.
4. Реализация или фактическое состояние.
5. Влияние на код и сайт.
6. Проверки и доказательства.
7. Ограничения и риски.
8. Rollback или процедура восстановления.
9. Следующее действие.
10. Журнал версий.

## 2. Метаданные

Используется таблица:

| Поле | Обязательное значение |
|---|---|
| Идентификатор | ID пакета или документа |
| Версия | SemVer либо версия паспорта/отчёта |
| Дата | Полная дата |
| Статус | Одно значение из словаря статусов |
| Основа кода | Точное имя актуального ZIP или commit |
| Связанный план | Версия PLAN_CURRENT |

## 3. Словарь статусов

| Статус | Значение |
|---|---|
| ГОТОВО К СТАРТУ | Пакет согласован, код ещё не изменён |
| ЗАПЛАНИРОВАНО | Пакет находится в очереди |
| В РАБОТЕ | Изменения начаты |
| НУЖНА ПРОВЕРКА | Код готов, требуется CI, VPS, API, production или E2E |
| ВЫПОЛНЕНО | Все критерии подтверждены |
| ЗАБЛОКИРОВАНО | Есть внешняя зависимость |
| ОТЛОЖЕНО | Не входит в ближайший MVP |

## 4. Карточка пакета

Каждый пакет оформляется по одному шаблону:

| Поле | Содержание |
|---|---|
| Цель | Какой риск или пользовательскую проблему закрывает пакет |
| Реализация | Что добавлено и как устроено |
| Изменённые файлы | Полный список новых и изменённых файлов |
| Влияние на сайт | Что увидит пользователь |
| Влияние на код | Какие границы и зависимости меняются |
| Проверки | Локальные, CI, production и ручные сценарии |
| Ограничения | Что намеренно не входит в пакет |
| Rollback | Как безопасно отменить изменение |
| Критерий завершения | Набор измеримых доказательств |

## 5. Правила таблиц и списков

- Короткие поля выравниваются по центру; описательные поля - по левому краю.
- Одна таблица отвечает на один вопрос.
- В ячейках используются короткие абзацы, а не длинные стены текста.
- Команды и пути оформляются отдельными code blocks.
- В каждом отчёте есть явные блоки `ПРОЙДЕНО`, `НЕ ПРОЙДЕНО`, `ОТЛОЖЕНО`.
- Источник факта отделяется от проектного вывода.

## 6. Правила экспорта DOCX/PDF

- Основной шрифт: Aptos или совместимый sans-serif, 10.5-11 pt.
- Заголовок 1: 18-20 pt; заголовок 2: 14-16 pt; заголовок 3: 12-13 pt.
- Поля страницы: 18-20 мм.
- Таблицы не используют одинаковую ширину всех колонок по умолчанию.
- Строки таблиц растут по содержимому; фиксированная высота запрещена.
- Заголовки таблиц повторяются на новых страницах.
- После каждого экспорта DOCX и PDF выполняется постраничный визуальный контроль.
