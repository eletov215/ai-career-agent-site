## 1. Решение о приёмке

Пакет JOB-001 принят после успешного CI №283 в основной ветке и последовательных подтверждений пользователя, включая завершающий блок. Принята обычная функция аккаунта: хранение вакансий и личных заметок на сервере. Генерация писем, произвольное сравнение резюме с вакансией и запуск Алисы в этот объём не входят.

Подтверждения сайта получены от пользователя. Состояние GitHub прочитано отдельно через подключение. Эти источники доказательств не смешиваются. Подробная матрица находится в JOB001_VERIFICATION_STATUS версии 1.2.

## 2. Подтверждённое поведение

Вакансии сохраняются из свежего поиска и остаются после обновления страницы и повторного входа. Повторное сохранение возвращает ту же карточку без дубля и потери заметки. Работают поиск по сохранённому списку, пустой результат и сброс фильтра.

Личная заметка сохраняется по явному нажатию кнопки. Устаревшая вкладка не перезаписывает новую правку; после конфликта можно продолжить работу через свежую форму. Старая форма удаления также не уничтожает карточку с более новой заметкой.

Экспорт содержит `saved_vacancies` и `saved_vacancy_sources`. Удаление требует подтверждения и затрагивает только выбранную карточку; её прежние страница и API больше не возвращают данные. Другие вакансии, профиль и резюме сохраняются. После выхода страницы требуют входа, а API отказывает в доступе.

Финальное подтверждение охватывает прежние функции сайта, сохранённую историю AI-003/004, закрытие временного AI-доступа, новую схему, ручной режим и просмотр логов Render. Содержимое личного экспорта и необработанные логи не собирались.

## 3. Отдельно зафиксированные ограничения

Ручная межаккаунтная проверка — **NOT RUN**: второго активного аккаунта нет. Наличие старых браузерных отметок и фактический результат их переноса отдельно не указаны. Проверка второго устройства также подтверждена только в составе общего блока, без отдельного результата. Эти условные сценарии не отмечены самостоятельными ручными PASS; автоматическое покрытие приведено отдельно.

Преднамеренный перезапуск сервиса, удаление реального аккаунта и искусственная очистка рабочей базы не заявляются. Создание точки восстановления Neon и восстановление рабочей базы отдельно не подтверждены. Проверка резервирования в CI относится к тестовым данным; эксплуатационная проверка остаётся в OPS-002/REL-001. Доставка писем новым аккаунтам и LEGAL-001 не закрыты.
