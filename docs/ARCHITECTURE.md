## 1. Назначение проекта

AI Career Agent — Flask-приложение для поиска вакансий из нескольких источников, загрузки и базового разбора резюме, а также подготовки будущих AI-функций карьерного сопровождения.

Основной пользовательский поток развивается в сторону:

```text
аккаунт -> карьерный профиль -> анализ резюме -> поиск вакансий
-> объяснимое совпадение -> письмо -> трекер откликов
```

Пользователь принимает окончательные решения самостоятельно. Автоматическая отправка откликов без явного действия пользователя не является целевой функцией.

## 3. Запуск приложения

Render запускает приложение командой:

```bash
gunicorn app:app
```

Главным исполняемым файлом остаётся `app.py`. Файлы наподобие `app_fixed.py` не создаются.

Перед созданием Flask-приложения `app.py` получает единый проверенный объект `SETTINGS` из `config.py`.

## 5. Конфигурационный слой

### 5.1 `config.py`

`config.py` является единственным местом прямого чтения переменных окружения. Он:

- определяет режим `APP_ENV`;
- проверяет обязательные переменные;
- валидирует Fernet-ключ;
- преобразует числа и boolean-параметры;
- проверяет диапазоны;
- формирует неизменяемый `AppSettings`;
- не выводит значения секретов в сообщениях об ошибках.

Поддерживаются режимы:

| Режим | Поведение |
|---|---|
| `production` | Значение по умолчанию и режим Render. Все секреты задаются явно. |
| `development` | Локальный режим; debug включён по умолчанию, но встроенных секретов нет. |
| `test` | Безопасные фиктивные OAuth-настройки; тестовый набор задаёт отдельный временный `DATA_DIR`, а синхронизация по умолчанию отключена. |

`render.yaml` задаёт:

```yaml
envVars:
  - key: APP_ENV
    value: production
```

### 5.2 Ошибка конфигурации

Production не должен запускаться с неполным окружением. При отсутствии обязательных переменных приложение завершается на старте с перечнем их имён. Секретные значения в сообщение не попадают.

Это предпочтительнее скрытой ошибки внутри OAuth-маршрута или пользовательского запроса.

## 6. Основные компоненты

### 6.1 `app.py`

Отвечает за:

- создание Flask-приложения;
- загрузку проверенного `SETTINGS`;
- маршруты сайта и API;
- пользовательские сессии;
- OAuth HeadHunter и SuperJob;
- SQLite-инициализацию текущего pre-MVP;
- объединение результатов провайдеров;
- локальный кэш Trudvsem;
- передачу данных в шаблоны.

В рамках `FND-002` бизнес-логика маршрутов и пользовательский интерфейс не меняются.

### 6.2 Провайдеры вакансий

Провайдеры изолируют работу с внешними площадками и возвращают `SearchResult`.

- `HeadHunterProvider` получает URL, фабрику заголовков, токен, debug-флаг и лимит валютного сканирования через конструктор.
- `ReedProvider` получает API-ключ через приложение.
- `SuperJobProvider` получает фабрики заголовков и действующего токена.
- `TrudvsemProvider` используется фоновой синхронизацией; пользовательский поиск читает локальный кэш.

Провайдеры не должны самостоятельно читать глобальное окружение.

### 6.3 `vacancy_store.py`

Содержит текущий SQLite-слой вакансий и фильтрацию локального кэша. Переход на PostgreSQL и доменные репозитории запланирован пакетами `DATA-001` и `DATA-002`.

### 6.4 Резюме

`resume_parser.py` извлекает текст из PDF и применяет эвристики. Это не настоящий LLM-анализ. Конструктор резюме работает в браузере и пока сохраняет черновик локально.

### 6.5 Шаблоны и статика

`templates/` отвечает за представление, `static/` — за CSS, JavaScript и изображения. Сетевые запросы, OAuth и работа с токенами не должны переноситься в шаблоны.

## 7. Поток поиска вакансий

```text
Форма поиска
    ↓
Маршрут Flask
    ↓
Проверенные настройки и выбранные провайдеры
    ↓
Прямые API-запросы + локальный кэш Trudvsem
    ↓
Нормализация
    ↓
Объединение результатов
    ↓
Шаблон vacancies_unified.html
```

Ошибка одного источника не должна скрывать выдачу другого. Это проверяется тестом.

## 8. OAuth и секреты

Рабочий OAuth-поток сохраняет проверку `state`. Токены шифруются Fernet-ключом из `TOKEN_ENCRYPTION_KEY`.

Запрещено записывать в репозиторий или логи:

- access token;
- refresh token;
- client secret;
- OAuth code;
- Fernet-ключ;
- содержимое пользовательской сессии.

HeadHunter и SuperJob являются внешними подключениями. Собственный аккаунт AI Career Agent будет добавлен позже.

## 9. Фоновая синхронизация

Текущая версия запускает daemon-поток Trudvsem из веб-процесса при первом запросе. В тестовом режиме он принудительно отключён.

Это временное решение. Пакет `SYNC-001` должен вынести синхронизацию в отдельный Render Cron Job или worker после подготовки постоянной базы.

## 10. Тесты и CI

`tests/` содержит:

- unit-тесты конфигурации, фильтров, парсера и хранилища;
- provider-тесты с mock-ответами;
- route smoke-тесты;
- subprocess-проверки импорта приложения в `production`, `development` и `test`;
- запрет непреднамеренного внешнего HTTP;
- проверку отказоустойчивости нескольких источников.

`.github/workflows/ci.yml` выполняет установку зависимостей, проверку чистоты репозитория, `compileall` и `pytest`.

## 12. Архитектурные правила

1. GitHub и актуальный ZIP — источник текущего кода.
2. Изменяется рабочий `app.py`, а не копия-замена.
3. Секреты задаются только окружением.
4. Прямое чтение окружения централизовано в `config.py`.
5. Test-only значения не переходят в production или development.
6. Ошибка одного провайдера не останавливает весь поиск.
7. Каждое изменение покрывается применимыми тестами.
8. После рабочего пакета обновляются CHANGELOG, ROADMAP и PLAN_CURRENT.
