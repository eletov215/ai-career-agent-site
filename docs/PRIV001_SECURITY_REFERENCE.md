## 1. Security boundary

Active first-party User + server-side AuthSession remains browser identity. Privacy export/delete routes are owner operations; possession of resume URL, OAuth identity or export filename is never identity proof.

## 2. Export controls

- login + CSRF + rate limit;
- owner-scoped database selection;
- no OAuth/auth secrets in serialized snapshot;
- ZIP generated in memory and response `no-store`;
- filenames generated by service, not user input;
- only owned ResumeAsset bytes included.

## 3. Delete controls

- login + CSRF + lower rate limit;
- exact confirmation phrase;
- current password re-verification;
- PostgreSQL User row lock;
- owner-scoped dependency counting;
- explicit local legacy OAuth cleanup;
- FK cascade owner subtree;
- browser session clear after success.

## 4. Audit minimization

`privacy_audit_events` deliberately has no User FK or identifiers. Allowed fields:

```text
event_type
bounded aggregate counts
created_at
random audit row id
```

Forbidden: user_id/email/external provider ID, filenames, hashes, contacts, profile/resume content, image bytes, cookies/session/OAuth tokens.

## 5. Threats and controls

| Threat | Control |
|---|---|
| export another User | authenticated owner scope |
| credential leak in export | explicit omission + tests scanning known secrets |
| CSRF destructive delete | Flask-WTF CSRF + SameSite/headers |
| stolen session deletes account | current password + exact phrase |
| deletion of another owner | user ID taken from authenticated `g.current_user`, never form |
| legacy token remnant | explicit HH/SJ legacy mirror cleanup |
| audit re-identification | no owner/provider identifiers; aggregate counts only |
| cleanup deletes active user data | only stale pending and expired/revoked auth predicates |
| huge repeated exports | rate limit + current bounded web-process implementation |
| rollback resurrects deleted account | explicitly not promised; restore only from verified backup decision |

## 6. Logging

Allowed telemetry:

```text
privacy_data_exported
privacy_account_deleted
privacy_retention_cleanup
aggregate category counts
```

Forbidden logging: request form password, exported JSON/ZIP, email/user ID, profile/resume state, asset IDs/bytes, OAuth credentials, cookies/session token.

## 7. Provider revoke caveat

Deletion removes local encrypted HH/SJ credentials. It does not prove the upstream provider invalidated its grant. Do not tell users that remote revoke occurred unless a future provider-specific revoke call returns verified success.

## 8. Retention worker isolation

Worker performs timestamp-based aggregate cleanup and emits identifier-free counts. It does not export data or inspect resume/profile content. On Render it is sibling process due staging service constraints; Compose/VPS can isolate it as its own service.

## 9. Incident response

On suspected privacy operation issue: disable affected route/worker via application deploy/config, preserve verified backup as appropriate, inspect secret-free event/request IDs, verify owner predicates and exported secret exclusions. Never request user to share export ZIP or credentials.

## 10. Rollback

Application revert can retain `0013`. Downgrade removes audit table only. A completed account deletion is intentionally not recoverable via schema rollback.

## 11. Residual risks

- synchronous in-memory export can become expensive with large BLOB volume;
- rate limiting uses staging memory backend;
- remote provider grant revoke absent;
- legal retention/consent wording pending `LEGAL-001`;
- future AI/JOB/BILL data must extend export/delete inventory.

## Hardened candidate v1.4.28

Повторный privacy/security аудит перед внешней проверкой усилил candidate: экспорт требует повторного текущего пароля и формируется как согласованный PostgreSQL snapshot; добавлены raw/archive size bounds, SpooledTemporaryFile, safe ZIP entry paths, OAuth profile sanitization и fail-closed owner/draft asset integrity. Account deletion повторно сверяет password hash под User row lock и использует единый lock order для Auth/OAuth rows. Retention cleanup получил bounded batches, orphan ResumeAsset cleanup (7d, только без current/history references), cross-process worker lock/heartbeat и индекс `idx_resume_assets_created`. Backup copies не переписываются account deletion; remote provider-side OAuth revoke не заявляется. Candidate schema остаётся `20260813_0013`; production до merge остаётся `20260812_0012`.
